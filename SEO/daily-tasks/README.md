# Ten-day SEO action plan

Updated 16 October 2026. This is the current execution schedule, replacing the earlier 12-week publishing schedule. Complete one main task each day, in order. Day 1 is the day you choose to start; record actual dates below.

The ten tasks cover the SEO setup, existing page improvements, resource publishing system, four initial guides, local and authority preparation, and release checks. Every task in the original 32-item backlog has an assigned day. All twelve content briefs are considered: four are the first writing assignments, and eight receive a publish, develop later, or hold decision. Producing all twelve finished pages is not the ten-day target.

## How to complete one task each day

1. Open that day's file and read its inputs.
2. Complete the checklist and save the stated output.
3. Check the finish conditions and record evidence.
4. Mark the day **Complete**, **Partial**, or **Blocked**, with the actual date.
5. Carry unresolved work forward with an owner or missing fact. Continue the next independent task.

Each file includes a prompt you can paste into an AI session. The prompt identifies that day's scope; it does not imply that the work has already happened. Before changing application code, follow AGENTS.md and the installed Next.js documentation.

Read [NEEDS-YOUR-REVIEW.md](../../NEEDS-YOUR-REVIEW.md) for missing facts. Record unknowns there instead of repeatedly asking the same questions. Contact email delivery and donation checkout stay deferred until approved configuration is supplied. Use the actual status in copy and reports.

The user clarified on 16 October 2026 that Search Console and other external admin setup belong to the superadmin. Use [SUPERADMIN-SETUP.md](../../SUPERADMIN-SETUP.md) for manual actions. Completing an SEO day does not authorize account/sign-in flows, verification, DNS changes, analytics installation, or sitemap submission on the user's behalf.

## What counts as complete

For code or copy work, save the finished change and its relevant checks. For a publication task, distinguish a finished draft, subject approval, a built page, and a published page. A draft waiting for review is **Partial**, not a published guide. A blocked configuration is not a completed integration.

If a whole day's task depends on missing access or facts, complete its fallback preparation and mark the remaining work clearly. The schedule can advance while that task remains partial. Do not mark all SEO implementation complete merely because ten calendar days have passed.

The initial four articles should be reviewed and published when ready, with their tools, metadata, hub links, and maintenance owners. The remaining briefs are handled as follows:

| B09-B12 Volunteer, partner, education, and mentorship pages | Day 3 decision for each page: justified, improve the parent instead, or hold | Actual operations, unique detail, working intake, responsible owner |

Creating eight extra placeholder pages is not part of the scope. Any additional production is scheduled explicitly after the relevant decision, without silently displacing the four initial guides.

## Follow-up after the ten tasks

- After the first complete 28 days of reliable measurement, prepare the first full performance report and set numerical goals from actual data.
- Check operational details and any local directory monthly; review general resources quarterly or sooner if a correction is needed.
- Revisit held briefs when the required facts, services, reviewers, and intake are available.
- At the quarter review, select the next content work using actual audience questions and performance.

These are handoff responsibilities, not scheduled reminders or automations. Search visibility develops after publication; the ten-day finish is the setup and content delivery record.
