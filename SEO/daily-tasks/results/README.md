# Daily result notes

Use this directory to record work when it is actually performed. No day has been completed merely because its task file exists.

Save one result file per day, such as `day-01-results.md`. Link it from the [progress tracker](../README.md) and include the actual completion date. Keep credentials and private records out of these notes.

## Suggested result format

- **Day and task:** identify the assigned day.
- **Actual date:** record the day work took place, using the project timezone.
- **Status:** complete, partial, or blocked.
- **Completed work:** describe the changes or decisions actually made.
- **Evidence:** link to saved files, source checks, commits, checked URLs, and real build/review results as applicable.
- **Publication state:** distinguish draft, approved, built, release-ready, and deployed.
- **Open items:** reference stable R IDs in the shared checklist, missing reviews, and unfinished implementation.
- **Next action:** name what needs to happen and who owns it if known.
- **Client update:** include a short numbered summary that reports only actual completed work.

For a completed deployment, include the deployed origin and live verification. For a pending release, state the exact next action. For reporting work, record the available collection period and avoid turning unknown metrics into zeros.
