# Program content expansion map

The website names ten program areas. This map explains how each could develop into useful search content if the underlying work becomes active. It does not assert that services, awards, referrals, workshops, or roles are available.

Use R02 and the individual program record in the root [review checklist](../../NEEDS-YOUR-REVIEW.md) before commissioning operational content. Keyword examples in this file are additional exploratory language, not measured queries or additions to the validated shortlist.

## Expansion test

Create a separate program page only when a visitor can make a practical decision from its unique content. At minimum, it should explain what is offered, by whom, where, for whom, when, with what limits, and how to ask or apply.

If a topic has only a mission paragraph, it belongs on the hub. If the useful answer is supplied by another provider, clearly identify that provider and avoid taking applications on its behalf. If details cannot be maintained, link to an authoritative maintained resource rather than duplicate changing information.

## Evidence before impact content

A program being planned is not an outcome. A delivered activity should have dates, scope, records, an accountable owner, appropriate permissions, and limitations. An eventual story can explain the experience and decisions without making a causal claim unsupported by evaluation.

## Search versus operations

Do not let a keyword platform decide which services the foundation appears to offer. Search demand can help prioritize useful explanations of actual work; it cannot establish capacity, eligibility, funding, safety, or permission to publish participant information.
