# Repository-managed website release — 22 October 2026

## User decision and implementation

The user chose to drop the CMS, manage content through the repository, and keep hosting fully free. Payload, OpenNext, CMS accounts/editor/API routes, database migrations, and CMS storage integrations were removed. The site again exports static HTML into `out/`; `worker/index.ts` handles contact requests. Version preview URLs are disabled in the Wrangler configuration.

All eight original designed pages are preserved, including the client's Georgia, United States and community-driven updates. Existing images, CSS, responsive layout, menus, program filtering, metadata, social image, and contact/donation setup-pending behavior remain. SEO research and the measurement specification remain; CMS-only article routes were removed, and no empty Resources hub was published.

`AGENTS.md`, the review checklist, the superadmin handoff, and [the repository editing guide](repository-editing-guide.md) now describe the user's final choice. R24-R26 are superseded by that choice, not pending CMS tasks.

## Validation completed locally

- Next.js production static build, TypeScript, ESLint, and Wrangler dry run passed.
- All 17 automated tests passed. The suite also verifies that `/admin`, account APIs, private previews, and the removed resource index return 404.
- All eight pages were compared at 1440px desktop and 390px mobile widths against the saved original design. Main content markup, titles, and descriptions match on every page. All desktop screenshots match pixel-for-pixel within the comparison threshold.
- Mobile image differences came from the browser selecting the existing 480w rather than cached 768w image. Comparing the same existing candidate removes those differences; the actual source images, crops, CSS, and srcsets are unchanged. The contact screenshot has 24px of trailing background beyond the original capture; all original rows match. See [the verification record](verification-2026-10-22.json).
- The packaged contact Worker is **1.95 KiB gzip**, with only the existing assets and rate-limit bindings. No CMS database or upload-storage binding remains.
- No real contact message or payment was sent. Email-provider responses in tests are mocked.

## Remaining configuration and dependency note

Contact delivery and donation checkout remain deliberately unconfigured (R05-R07). Exact legal identity, approved registration status, and active-program details remain unresolved. Search Console, analytics, and domain setup remain with the superadmin.

The installed dependency audit reports five high-severity entries along the Next ESLint tooling chain through `braces`; `npm audit --omit=dev` also retains a `braces` advisory because the lockfile marks it `devOptional`. `npm explain braces` resolves its installed path through `eslint-config-next`. This parser is not bundled into the deployed static assets/contact Worker, which has no Next or CMS server runtime. The suggested automatic fix downgrades the Next ESLint config across major versions, so it was not applied. This is not a clean dependency audit or a full security audit.
